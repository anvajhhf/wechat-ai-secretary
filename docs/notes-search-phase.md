# 第三步：笔记检索与有来源的问答

负责人：主代理 `/root` 全程负责范围、集成、分歧裁决、验收和逐档案启用。`chat_core` 实现独立索引与核心测试；`chat_test_plan` 实现会话和生命周期测试；`chat_review` 独立审核。所有子代理继承主任务模型与推理强度。

## 本阶段范围

- 每个档案明确列出允许文件或目录；无 allowlist 不启用。当前真实配置为两个不同 Vault，首次仅各自 `Inbox/微信收件箱.md`，共同排除双方 PrivateInbox。扩展共享目录表示明确共享，不以来源 ref 哈希推断归属。
- 本地搜索不调用模型，最多返回 5 个片段，支持短中文、混合词、标签及上海日期条件。记录日期取明确来源日期，不以文件修改时间冒充记录时间。来源包括相对路径、标题、日期、行号和文件版本。
- 单次笔记问答只接收当前有效来源，不接收普通聊天历史、记忆或工具。程序校验引用编号并附来源；编号合法不等于模型事实绝对可靠。只在非私密问答时将这些限定片段交给既有模型。
- 检索结果短期有效，发送确认后才可追问，重启不恢复。新搜索、话题切换、其他操作和过期会失效；问答不进入普通聊天历史或长期记忆。
- 分别在查询、问答生成前、生成后及实际适配器调用前检查当前文件/内容版本。失效则拒发旧正文；进入发送接口后无法撤回已在途消息。
- 独立 `notes-index.sqlite3` 可重建，持久排除控制在 `runtime/notes-control/<profile>/control.json`。排除整个来源文件，原文保留。禁止缺失/损坏控制时重新索引已存在状态；不承诺同时回滚索引和控制文件后的检测，也不能辨认离线改写的未知副本。
- 笔记保存完成后仅通知后台扫描；扫描故障不影响保存结果。检索异常不回退为任务执行或普通模型猜答。

## 分歧、依据与处理共识

1. 审核提出共享 Vault 不能推断档案归属。负责人核对实际配置后确认 Vault 分离，首次仅独占收件箱；配置层明确允许共享即共享，不宣称跨档案内容自动隔离。双方一致。
2. 审核建议检索内容不写通用聊天，避免来源删除后衍生复活。负责人采纳独立短期焦点，并保留原聊天、记忆机制；双方一致。
3. 对按段排除还是按文件排除，依据收件箱追加格式及块边界可编辑，双方选择整文件持久排除，回复明确告知同文件全部笔记会受影响。关闭搜索时仍允许用已知来源 ID 排除，旧编号不恢复。
4. 发送链保持阶段二三态规则：确定旧版本丢弃；验证异常不保存正文但仍执行已送达后的任务焦点安全屏障。固定锁顺序 memory → notes focus → notes index；不跨网络 await 持锁。审核与实现意见一致后实施。
5. 审核在 Windows 复现目录 allowlist 使用 `normcase` 后反斜杠与前缀斜杠不一致，负责人和实现者核对后统一分隔符；明确文件与目录子文件分别测试。审核又发现 Vault 祖先 junction 可能绕过目录边界，达成一致逐级拒绝所有祖先链接，并比较私密路径的实际目标。
6. 审核复现失败错误码 `chat:notes-` 与账本约定 `chat-` 不匹配，可能重放模型。负责人改用已有常量；测试固定同 ID 不重试、新 ID 可重试，保持其他操作原重试语义。
7. 审核指出原集成无条件获取索引锁会让普通记忆聊天等待扫描。负责人核对同意按本次结果选择依赖锁；普通聊天不调用笔记发送门闩，只有同时依赖时保持固定顺序。新增故障隔离测试。
8. 负责人和审核分别发现 UTC 来源日期跨上海午夜时会落入错误日期；实现者确认转换 UTC+8 后筛选，纯日期不变。重建索引提升控制版本，使旧编号失效，排除集合保留。
9. 审核复现 frontmatter 的 `private: true # comment`、`privacy: private # comment` 及超过 100 行预算后才出现私密键可能漏判。双方选择有限保守解析：注释/引号正确处理，重复或未知隐私值、无法在预算内找到 frontmatter 结束符均整文件拒绝。
10. 审核复现无效的新搜索保留旧编号。负责人同意所有新搜索尝试都先清旧焦点，再检查空条件、长度或图片；测试保证失败后不能按旧编号排除。
11. 核心测试发现 Windows Python 3.13 的 `lstat` 和 `fstat` 对 ctime 表达不同，正常文件会误判为改动。负责人、实现者和审核核对证据，同 API 前后保留 ctime 比较，跨 API 比较设备/文件身份/大小/mtime，仍读取并校验内容 hash，不放宽实际来源验证。
12. 实现自查提出目录枚举改为流式限量、读取权限或解码错误明确不可用、同轮扩充排除标识后重筛已读来源。负责人认可其符合有界扫描和不能把失败称为无结果的要求；与审核同步后实施。

- 独立审核另行运行 90 项新增测试，3.606 秒全部通过。无剩余代码阻塞项或未达一致事项。阶段说明集中记录全部讨论，审核没有直接替代执行判断。
- Windows 测试使用正常本机权限验证路径与事件循环，未为受限运行环境放宽产品校验。Python 编译、部署脚本语法、`git diff --check` 与仓库当前文件/可达历史凭证扫描通过；README 仅有既有换行提示。
- 已沿用用户授权方式逐个启用，先 owner 再 partner，分别核验在线与健康看护。真实模型回答质量及真实微信送达不在本轮测试结论中。
