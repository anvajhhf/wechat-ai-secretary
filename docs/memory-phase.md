# 长期记忆：第二阶段实施说明

日期：2026-10-22。全程负责人：主代理 `/root`。用户要求先做长期记忆，故将原规划 C 提前作为第二步；笔记检索仍未实施。状态：开发、803 项全量离线验收及独立审核完成，已按 owner → partner 顺序启用并通过真实进程及连接检查。未向微信发送测试消息或运行真实模型验收。

## 范围与分工

只处理用户明确要求保存的事实、沟通偏好、背景、目标及项目资料。普通对话不自动提取个人画像；记忆只作为无工具聊天的参考，不进入提醒或笔记的动作分类器。

`/root` 负责整合、发送边界、配置、验证与最终交付；`chat_core` 负责存储、命令解析与存储测试；`chat_test_plan` 负责独立兼容及生命周期测试；`chat_review` 独立只读审核。所有代理继承主任务模型与推理强度。执行与审核先对照代码、复现及方案依据讨论，再实施相关改动。

## 已核对的取舍与处理方案

| 议题 | 依据与讨论 | 一致处理方案 |
|---|---|---|
| 第二步范围 | 原规划先笔记检索再记忆，用户此次明确先长期记忆 | 提前完成记忆，笔记检索保留为后续；不声称三步已全部完成 |
| 记忆范围 | 审核最初考虑同用户跨聊天共享；现有队列、聊天正文和焦点均按 conversation_key 隔离 | 负责人、实现、测试及审核确认用档案 + 账号 + 用户 + chat_id。新话题仍使用同会话记忆，换 chat_id 不自动共享 |
| 清除旧事实与派生回答 | 现有聊天正文没有完整逐轮来源关系，只删 memory 行不能防旧回答再次召回 | 新增、更正、忘记及到期在同库事务内换聊天代际并清空该会话全部已保存聊天，删除控制不留原正文；提醒与原笔记保留。明确告知清理范围 |
| 恢复旧数据库 | 同库 tombstone 会随旧备份一起倒退；现有备份脚本不备份 assistant.sqlite3 | 在 state 目录外保留每档案 guard，核对数据库身份和全局版本；不匹配、控制缺失或未能证明完成的写入，使记忆与可能含旧事实的历史停止使用。故障时普通聊天只用当前输入，其他执行器照常 |
| 未发送回答失效 | 仅发送后不入库无法阻止旧正文送出，事件循环排队还有额外延迟 | 实际交给适配器前与确认发送后均检查记忆版本及聊天代际；最终版本检查与创建适配器请求使用同一短锁。网络等待不持锁，已经交给适配器的请求视为在途，不能承诺撤回 |
| 功能关闭 | 旧聊天可能已经包含记忆事实，单停注入仍会从 history 带入 | 含记忆上下文的聊天轮次标记来源；关闭后过滤这些轮次，后续普通无记忆聊天可继续。关闭停止新增和更正，仍可查看及明确忘记已有记忆 |
| 私密、临时与旧命令 | 记忆命令不能抢占私密保护、显式聊天、任务和笔记前缀，旧无冒号“记住明天提交报告”可能本来建任务 | 授权及媒体隐私检查先行，显式聊天/临时聊天拥有正文；其后仅识别锚定外层的明确记忆语法。记忆管理结束旧任务草稿和匿名焦点，不对提醒、笔记作副作用 |
| 回执时记忆读取失败 | 审核指出初实现将“明确版本已变”与“读不到版本”都提前返回，后者可能跳过阶段 A 已有的任务焦点失效；测试用发送期间提醒写焦点的交错复现 | 负责人核对后同意三态处理：明确过期才跳过；读取异常只禁记正文，仍执行焦点 reset 与原故障恢复标记。固定用例通过 |
| 超时后的发送回调 | 审核及负责人发现循环闭包会在超时后被下一条消息覆盖 | 用默认参数冻结当次消息和结果；保留送达不明不重发。固定测试延后两条回调，确认各自仍绑定原消息 |
| 安全替代回复与历史 | 审核指出在适配器边界仅替换字符串、回执却记原结果，会在瞬时故障恢复后把未发模型正文记入历史 | 工作线程先将结果替换为实际待发结果；事件循环边界若再失效则不调用适配器。确认回执只针对实际结果，两个故障恢复用例通过 |
| 关闭且守卫缺失 | 审核构造旧库仍有 memory_meta、关闭记忆且guard缺失；只看开关/guard会绕过恢复校验 | 负责人、实现及测试同意只读检测既有记忆表；存在或无法确定时仍验证，失败则空历史。不把可检测旧库当作从未启用 |
| 旧裸记住语法的测试依据 | 测试初假定“记住明天提交报告”原本建任务，实际开关两组都走既有聊天；普通 fact 也不能按常驻偏好期待 | 固定开关前后一致性，并用既有“记着买血压计”验证原任务路径；事实查询带相关关键词，常驻偏好显式标类型。调整错误测试假设，不扩大旧词法 |
| 逐个启用时健康任务竞态 | 审核发现上阶段运维停止脚本只请求停止健康任务，没有确认退出；健康恢复可能与新启动交错 | 负责人核对既有自启动配置脚本后同意：本阶段运维副本增加最多 10 秒退出等待、再次检查启动任务 Ready；超时保留维护并中止，不修改产品逻辑 |
| 进程档案参数核验 | 审核指出 owner 的 HERMES_HOME 路径是 partner 路径前缀，Contains 不足以证明参数精确匹配 | 双方核对实际启动参数后同意改为完整参数边界匹配，最终核验同时检查 PID、启动时间既有容差、state.home、实际参数及连接状态。未放宽严格停止工具校验 |

记忆每轮从当前数据库读取，使用独立长度预算；少量沟通偏好固定提供，其他事实按本轮关键词选择。没有向量检索和任意语义冲突识别；同名冲突要求明确更正，未知矛盾不能自动判为真相。长资料应继续保存为笔记。

到期条目在启动、记忆访问与发送前校验时失效并清理，进程停止期间不执行清理；不会把到期事实用于新的模型请求或通过最终版本校验。首版没有为记忆增加独立后台调度器。

## 恢复与能力边界

守卫位于 `runtime/memory-control/<profile>/guard.json`，正文位于各自 `runtime/state/<profile>/assistant.sqlite3`。不得为了让旧数据库通过检查而删除或重建守卫。若无法取得最新控制记录，应保持记忆不可用，人工核对恢复来源。整个磁盘快照同时倒退数据库和守卫无法在本机自行证明，当前不承诺检测或物理擦除该类未知副本。

“忘记”不撤回已发微信消息，不删除原 Obsidian 笔记，不处理未知同义副本。对已追踪派生聊天采用整会话清理，因此会丢弃该会话中无关的近期聊天；这是首版可验证遗忘的明确代价。已排队的请求按原 FIFO 处理，变更以数据库提交为生效点。
