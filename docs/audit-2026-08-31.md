# 2026-08-31 重复提醒、自然纠错与本地语音模型更换审核

> 这是特定历史版本的审核快照。进程、备份和提交状态均可能已经变化，请以当前代码、CI 和本机状态检查为准。

本轮在 `febb54e` 基线上实施。主 Agent 负责整合和原始语音回放，独立审查覆盖重复规则与来源边界、草稿续接与隐私、语音安全与成本，并相互复核。两套运行网关随后逐套切换至 Paraformer；下文区分离线验收与实际部署核验，不将进程就绪等同于真实任务创建成功。

## 根因与整改

- 截图中的微信转写不是秘书实际收到的转写。仅在本机回放对应原始音频，确认现有 `small` 模型把“明天”识别成“每天”；按截图文字直接输入则能正确生成次日14:00的单次提醒。不能把这两条链路混为一谈。
- 原来的“不支持重复”提示无论是否提供次数都声称“记住了事项和次数”，也没有说清已经听到“每天”。现按实际频率、时间和次数生成提示，不虚构缺失字段；无文字说明、无图片的单附件非私密语音，在新任务语义校验需要澄清时显示有限长度的实际转写，草稿续接不额外回显。
- 新增只作用于当前未执行草稿的明确单次纠正：“不是每天，是明天”“就明天一次”“明天提醒我一次”等会保留事项及未修改的时间。仅补日期不自动取消重复规则。取消、问句、引用、新任务、跨会话、过期、乱序、已处理或结果不确定的状态仍受原有保护。
- 提醒次数改为只取外层指令和与提醒动词直接绑定的数量。正文、引用、前置事项中的次数不能悄悄改变频率或生成更多提醒。旧草稿中的0仍表示未提供次数；明确输入“共0次”会单独保留为无效要求，不能变成默认次数或单次提醒。
- 模型生成的提醒字段在进入任意澄清分支之前清空，仅根据用户提供的控制字段重建，防止模型猜出的重复规则在后续补充时变成所谓的“原始信息”。
- 语音本身及多个语音片段分别检查口述私密前缀；文字说明、强制待办前缀和媒体展示标签不能遮蔽私密要求。任何候选转写中发现私密前缀后都拒绝后续处理，不能被恢复识别覆盖。事先文字标记私密仍在 ASR 前拦截。

## 第一阶段：Whisper 诊断（历史对照）

此阶段尚未获准换模型；以下保留为诊断依据，不代表第二阶段选型结果。

- 沿用缓存内的 Whisper `small`、CPU `int8` 和现有依赖，不下载权重、不新增云端语音服务。语言直接读取档案设置；原先实际运行环境已经是中文，不能将本次错误归因于“未设置中文”。
- 项目内识别器明确限制 `local_files_only`，预先检查模型和 tokenizer 缓存，缺失时拒绝处理。模型加载、分段迭代及恢复都在实例锁内；不借助进程环境传递单条请求，不读取历史消息。
- 使用小型静态领域词表改善术语。原始样本中的“试剂和”改善为“试剂盒”，但“明天/每天”仍未可靠区分。不同采样、解码参数及 CPU float32 对照没有解决该日期错误，因此不增加部署体积或启用更重计算配置。
- 实际合成语音对照发现，词表会干扰约2至3秒的短句。现在不超过4秒或无法读取时长的输入不加词表；该时长包括停顿，只是保守策略，不是识别准确率保证。
- 空转写、非法置信度、超长内容及后端异常直接拒绝；异常压缩比、替代字符或重复标点等明确质量问题，最多在本地去掉词表恢复一次。静音和私密信号不重试；普通词语差错也不会触发循环识别。

- 用实际 ASR 回放原始语音，进入完整秘书服务后停在明确的“每天”澄清，未创建任务；随后输入合成语音“不是每天，是明天”，沿用原事项，模拟生成 `2026-09-01T14:00+08:00` 的单次提醒，重复规则为空，只有一个任务。
- 该验收使用固定参考时间 `2026-08-31 19:11:59 Asia/Shanghai`、内存状态库和假外部执行器；进程内禁用网络。完整对话的理解模型调用数为 **0**，未调用真实 DeepSeek、滴答或微信发送接口，未改动生产数据库。
- Python 编译、PowerShell 脚本语法、仓库差异检查和凭证扫描一并核验；原始音频、真实凭证、生产日志及模型权重不纳入版本控制，合成语音只作本地临时验收资料。

## 新后端安全、兼容与原生验收

- 新后端使用真实16kHz单声道重采样、有限音频长度、本地Silero人声检测和逐条独立识别流；人声检测不裁剪私密前缀。禁用不受这两个原生后端支持的热词接口，避免原生进程退出。未知或损坏文件/语言/线程配置安全失败，不伪造Whisper置信度。SenseVoice原生`result.lang`中的无语音信号与正文前缀信号均受检查。
- 独立审核指出并修复：识别器常不输出标点，明确每周指令后的句尾“共三次”需同时进入次数提取和标题清理。只接受已确认外层每周规则的完整句尾总次数；统计活动、正文后续词、引用和多个不同次数不会被当成可靠总次数。引用掩码不能让后续正文消失。
- 已有唯一提醒可用“不是三点是两点”“不是明天，是后天”纠正。只接受负、正两侧都为纯时间字段，复用原有任务、时段、唯一上下文和快照校验；取消、问句、新事项、多候选、过期、乱序及过去时刻不能绕过保护。
- 不同次数与“三四次／两三次／三十十次”等不可靠次数会使旧草稿次数失效并追问；不能只补一个时间就沿用旧次数创建。明确新次数后才恢复。同值重复和正常中文数字仍可用。
- 实际原声通过正式项目环境的ASR进入内存服务，在固定参考时间下生成一个模拟任务、次日14:00的单次提醒；今日16:30、每周二09:00共3次、正文“统计共三次报价”均正确。实际合成语音“不是三点，是两点”在创建后正确重排为14:00，旧15:00记为rescheduled，不新建任务。
- 上述原生端到端验证禁用网络，只用内存状态库和假执行器；DeepSeek调用0，没有真实滴答任务、微信消息或笔记写入。生产数据库未被用作测试。
- 120秒合成语音单进程约6.8秒、峰值541 MB；两套隔离进程并发复核均约7.6秒，合计进程树峰值约1104 MB（含Windows Python启动器子进程）。同机另一次高负载并发约18.6秒，故不承诺固定延迟。20秒静音与随机噪声均在本地拒绝。内存是独立ASR测试进程值，不等于整套Hermes网关的总内存。
- 最终全套 **585 项离线测试通过**：第一阶段472项，加ONNX语音43项、创建后纠错17项、无标点与次数边界29项、启动检查24项。Python编译、25个PowerShell脚本语法、仓库凭证扫描、依赖检查及完整模型复核通过；单元测试不下载模型、不读取用户原声。原声仅在用户授权的本机原生验收中使用，不进入版本控制。

## 成本、剩余限制与部署边界

- 不增加 DeepSeek 上下文、历史或二次模型审核。本轮已验证的明确提醒和纠错路径为零 Token；复杂消息仍按既有规则调用模型，不能承诺整个系统的所有消息均为零成本。
- 尚未支持无限每天/月度等重复提醒，不会把真正的“每天”偷偷改成“明天”。新模型改善了本次日期错误，但术语、口音、噪声仍可能造成识别错误，不能保证任意语音完全正确。
- 当时的新代码已在本机两套网关运行；模型、原声、凭证、生产日志及备份均保持本地隔离。既有任务、两套凭证及已取消的 08:00/22:00 汇总未改动。该句仅记录当时状态，不描述当前提交或部署。
- 自动测试、真实音频回放、独立审核和上线就绪核验提供了具体证据，但不是无缺陷保证；后续真实使用仍可能暴露术语或环境差异。
