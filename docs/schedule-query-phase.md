# 安排查询与汇总

日期：2026-10-26。负责人：主代理 `/root` 负责实现、核对依据、自查、测试和逐档案启用。本阶段没有新建或委派子代理，未声称独立代理审核。

## 范围与使用

用户可直接问“今天有什么事”“这周有哪些提醒”“有没有没做完的”“查一下逾期任务”，或发送“安排查询：下周”。截图原话“最近有什么要提醒我的事情吗？本周要做的。”按本周解析。

- 今天、明天、后天按上海日历日；本周为周一至周日，下周为下一自然周。“最近/近期”未另限定时按未来7天（含今天）；支持 YYYY-MM-DD 或最多31天的明确日期区间。多个冲突范围先澄清。
- 汇总当前收件人的本地提醒和当前档案所连接滴答账号的未完成待办。两档案分别使用自己的配置和连接；若人为授权同一个滴答账号，该账号的数据本身就是共享的，程序不推断每条远端任务的微信归属。
- 本地提醒严格按 platform/account/user/chat 过滤；查询只读队列，不认领、重发、取消或修改状态。滴答仅调用一次 `filter_tasks`，不启用模型或通用代理工具。没有从聊天、长期记忆、笔记或外部日历推测安排。
- 返回截止/开始/提醒时间和相应状态。截止日全天任务到上海次日零点才算逾期；只有开始时间的任务不冒充截止时间。无日期待办不自动归入本周，提供数量并提示查看全部未完成待办。
- 只按稳定的 project_id + task_id 合并已关联的任务与提醒；同名不同 ID 保留。任务 ID 不截断，冲突重复记录不任意选版本。
- 每日滚动提醒库只保存下一次；范围内后续日期按已有有效规则推算，标为“按每日规则预计，届时仍需发送”，不往队列写入记录。已取消/改期/停止的规则不投影；实际已有记录优先于同一天投影。
- 提醒“已发送/发送失败/送达未确认”不代表任务完成。已发送提醒可在对应日期范围查看，但不纳入“全部未完成/逾期”的本地未确认列表。
- 数据源失败、未识别返回结构、分页未取全、坏日期或超过上限都会说明不完整；不能将失败当作没有安排。最多各读取2000条，最多展开12项和每项4次提醒，超出明确告知。
- 查询摘要不写入通用聊天历史或长期记忆，也不成为编号完成/取消目标。查询清除旧笔记编号及旧任务指代；后续实际操作仍走原明确命令和核验流程。私密、临时聊天、显式聊天、笔记保存、长期记忆与提醒创建优先级保留。

## 依据、取舍与修正记录

1. 现有普通聊天不读待办/提醒，已有任务查询只读滴答，无法覆盖微信本地提醒。因此新增独立只读入口、单独开关，旧开关缺省不改变原路由。
2. 现场只读工具发现确认 `filter_tasks` 参数为 `{filter: {status: [0]}, client_timezone: "Asia/Shanghai"}`；日期查询工具要求嵌套 search 且最大14天，本阶段使用一次未完成列表读取并在本地按上海日期筛选，不复制旧日期参数假设。
3. 实际只读返回为 `result` 内任务数组，普通任务 kind 为 `TEXT`，与 MCP 描述中 TASK 不同。第一次真实解析因严格类型校验明确报告不完整，未冒充空成功；补充 TEXT 合同和固定测试后两账号均完整解析。此过程只输出结构/枚举/条数，未输出任务正文。
4. 自查发现带时间的普通陈述（如“今天我有事”）可能被宽泛语法识别为查询；收紧为明确读请求或名词式查询，并加聊天边界回归。创建提醒和含引用、否定、讨论的文本不据此触发安排读取。
5. 自查发现同一来源 ID 的不同日期记录不能随意保留第一条；标记不完整并剔除冲突身份。无日期且已通过关联提醒显示的任务不再重复计入“另有无日期待办”。
6. 不新增主动日报、定时汇总或后台任务查询。用户每次查询才读取实际来源；保持现有提醒调度与健康看护。
